# Landing page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Landing publique sur `/` pour les visiteurs non connectés (connectés → `/dashboard`), hero en deux colonnes illustré par de vraies captures générées depuis une base de démo isolée contenant 10 guides techniques réels.

**Architecture:** Composants serveur dans `components/landing/`, rendus sans montage différé (`SiteChrome` traite `/` comme `/auth`). Le script de `<head>` masque la landing si un token existe ; un îlot client redirige. Les guides sont des fichiers markdown à en-tête, validés par des tests ; un stack Docker séparé (`docker-compose.demo.yml`) sert à les importer et à capturer la page doc.

**Tech Stack:** Next 14.2 App Router, Tailwind v4 + tokens, `next/image`, `node --test`, `playwright-core`, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-29-landing-design.md`

## Global Constraints

- Fonctionnalités réelles uniquement ; textes de la maquette validée (spec §2).
- Tokens uniquement, aucune couleur en dur dans le TSX.
- La landing est dans le HTML serveur (pas de montage différé).
- Aucune modification de `services/api`.
- Guides : contenu exact, commandes fonctionnelles, 60–120 lignes, ≥ 2 titres `##`, techno en minuscules, slug unique.

## Review Focus

1. **Connecté arrivant sur `/`** → jamais de flash de la landing ; arrivée sur `/dashboard`. (Test : Task 2, flows + test unitaire du script.)
2. **`localStorage` bloqué** → le script de `<head>` ne casse rien, la landing s'affiche (visiteur traité comme non connecté). (Test : Task 2, unitaire.)
3. **`/auth?mode=register`** → onglet inscription ouvert ; `/auth` seul → connexion. (Test : Task 2, flows.)
4. **Guide mal formé** (en-tête manquant, slug dupliqué, techno en majuscules) → test rouge. (Test : Task 1.)
5. **Capture reproductible** : relancer `landing:capture` sur une base vide donne une page doc sans donnée de test. (Test : Task 3, exécution réelle + relecture.)

- [ ] **Step 1: Tests (RED)** — `landing.test.ts` exécute `landingInitScript` contre un faux `document`/`location`/`localStorage` : `/` + token → `data-authed` ; `/` sans token → rien ; `/docs` + token → rien ; `localStorage` qui lève → rien, pas d'exception. `flows.mjs`, section « landing » placée **avant** l'inscription (visiteur non connecté) : `/` → un `h1` contenant « enfin au même endroit », lien « Créer un compte gratuit » → `/auth?mode=register`, l'onglet actif y est « Créer un compte » ; ancre `#features` présente ; image du hero chargée (`naturalWidth > 0`) ; HTML serveur de `/` (via `fetch`) contient « enfin au même endroit ». Nouvelle vérification après la connexion : `/` → URL finale `/dashboard` et la landing n'a jamais été visible (observer `h1` landing absent au premier rendu).
- [ ] **Step 2: `lib/landing.ts`** + injection du script dans `app/layout.tsx` après `themeInitScript` ; CSS : `html[data-authed] [data-landing] { visibility: hidden; }`.
- [ ] **Step 3: Composants** (textes de la spec §2, mini-visuels mono des fonctionnalités, images `public/landing/hero-{dark,light}.png` via `next/image` — Task 3 les produit ; en attendant, une capture provisoire du stack local est acceptable pour le développement).

- [ ] **Step 5: Inscription directe** — `auth-panel.tsx` : onglet initial lu depuis `useSearchParams().get("mode") === "register"` ; `app/auth/page.tsx` enveloppe `AuthPanel` dans `<Suspense>`.
